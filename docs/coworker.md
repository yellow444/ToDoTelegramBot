# Claude и Codex как коворкеры бота

Простое (напоминания, переносы, «что у меня сегодня») делает сам бот на локальной LLM через
`llm-gateway`. Сложное (код, исследования, многошаговые дела, планирование) уходит коворкерам:
**чатам в десктопных приложениях Claude и Codex**, по подписке, без API-ключей и без CLI.

Задание попадает в очередь одним из способов:
- `/claude [папка] текст` или `/codex [папка] текст` в Telegram;
- кнопка «🤖 Поручить» в меню «⏰ Когда» у любой задачи;
- ассистент бота сам передаёт сложное (`? попроси Claude разобраться с тестами в todo`);
- другой агент через MCP-инструмент `delegate_to_agent`: Claude может поручить что-то Codex и наоборот.

Отчёт приходит в Telegram. Ответ на отчёт (reply) продолжает разговор: чат получает историю предыдущих шагов.

Папки проектов задаются в `.env`: `AGENT_WORKDIRS=todo=F:\...\ToDoTelegramBot;gw=F:\...\llm-gateway`.
Задания без проекта выполняются в `AGENT_HOME`.

## Когда приложение закрыто

Задания выполняет открытый чат-коворкер. Если приложение закрыто:
- `/claude` и `/codex` честно отвечают, что коворкер не на связи и задание ждёт в очереди;
- утренний и вечерний разбор дня (`/orchestrate claude`) не копятся: новый заменяет невзятый старый,
  а невзятый за `ORCHESTRATION_TTL_HOURS` (12 ч) тихо отменяется. Карточек в чате разбор не создаёт,
  приходит только отчёт;
- задание, которое чат взял и не сдал (закрыли приложение), через `AGENT_TIMEOUT` помечается как неудачное.

## Чат-коворкер (основной способ)

Вся работа с ботом идёт в одном чате. Он ждёт задания скриптом (токены при этом не тратятся),
выполняет их и держит контекст. Когда чат пора сменить, новый чат читает журнал
`agent-context/claude.md` (или `codex.md`) в папке проекта и продолжает с того же места.
Отдельные запуски по расписанию не нужны: утренний и вечерний разбор бот сам ставит в очередь
этому чату (`/orchestrate claude`).

Вставьте в новый чат (Claude: Code-вкладка десктопного приложения, папка проекта ToDoTelegramBot):

```text
Ты — мой коворкер из Telegram-бота задач. Сначала прочитай agent-context/claude.md: там правила и история.
Работай по циклу:
1. Запусти в фоне (run_in_background):
   .venv\Scripts\python.exe -m todobot.worker --wait claude
   Команда завершится, когда придёт задание, и выведет JSON: job, task (текст, расшифровка, вложение), instructions.
2. Выполни задание по instructions в папке job.workdir_path.
3. Сдай отчёт: .venv\Scripts\python.exe -m todobot.worker --report <job_id> --file <отчёт.md> (или --fail).
4. Допиши 2–5 строк в agent-context/claude.md и вернись к шагу 1. Между заданиями ничего не пиши.
```

Для Codex (десктопное приложение) замените `claude` на `codex` и журнал на `codex.md`. Codex не умеет
просыпаться от завершения фоновой команды, поэтому ждите с таймаутом в цикле: `--wait codex --timeout 600`.

## Фоновый CLI-воркер (не используется)

В коде есть режим `python -m todobot.worker` без `--wait`: он сам запускает `claude -p` или `codex exec`.
Ему нужны CLI с отдельным входом. У Максима стоят десктопные версии, поэтому этот режим не используется
и не настроен.

## Задачи из Telegram как материал для агентов

- У каждой карточки есть `#id`. Агент получает задачу через MCP `todo.get_task('#abc123')`
  (или по номеру сообщения): текст, исходная подпись, расшифровка голоса или видео, текст с картинки, время.
- `todo.download_attachment('#abc123')` скачивает файл вложения в `data/files` и возвращает путь на ПК.
- `/claude …`, отправленная ответом на карточку, отдаёт агенту именно эту задачу вместе со всем её содержимым.
- Ответ на карточку текстом («перенеси на пятницу», «? о чём это») обрабатывает ассистент бота
  применительно к этой задаче.
